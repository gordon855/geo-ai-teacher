# 21.4 → 21.5：Workbench升级与LiteAvatar一键启动

适用：网站21.4.0正在运行；Windows电脑上的WSL Ubuntu用户为gordon，之前已经跑通OpenAvatarChat、LiteAvatar、SSH隧道、HTTPS数字人入口和TURN。升级脚本同时兼容21.2.0、21.3.0直接升级。

这是完整21.5源码包，不是在线升级已经完成的证明。云端网站升级和本机启动器安装分开进行。云端升级在阿里云Workbench；启动器放在你运行数字人的Windows电脑上。

## 1. 本版变化

| 需求 | 21.5实现 |
|---|---|
| PPT真正全屏 | 只把幻灯片舞台进入浏览器全屏，隐藏工作台、翻译侧栏；同时按屏幕宽度和高度适配完整页面。比例不同时留黑边，不裁剪、不拉伸。 |
| 全屏操作 | 左右方向键/PageUp/PageDown翻页；Esc退出。鼠标移到底部显示控制栏，也可用Tab聚焦按钮。 |
| 测绘翻译显示 | 选词、拖选短语或双击整句后，译文以底部覆盖字幕显示；可随时关闭。采用固定字幕，便于课堂阅读。 |
| 翻译声音 | 点击“朗读译文”，或打开“自动朗读”。采用浏览器/系统语音，不额外调用百炼TTS；切页、更换选文或点击停止会取消旧语音。翻译生成仍使用原课程接口。 |
| LiteAvatar启动 | Windows双击启动器后自动调用WSL、启动数字人、连接原SSH隧道。无需每天打开两个Ubuntu窗口。 |
| 网页启动入口 | 教师PPT讲授台新增“一键启动本机LiteAvatar”。第一次安装协议后可点击唤起；浏览器可能要求确认打开程序。 |
| 开机使用 | 可选择Windows登录后自动启动课堂服务；需要电脑开机、登录、联网且不休眠。网页不能唤醒关机电脑。 |

保留21.4的课件库、批量上传、课件选择、LiveAvatar/LiteAvatar课堂切换、随机点名提问、PPT本页讲解、签到及照片人数核验等现有功能。课堂通信接口仍叫teacher213，属兼容设计，不代表版本未升级。

## 2. 下载文件，区分放在哪里

- `surveying-ai-teacher-v21.5.zip`：网站完整源码，上传阿里云服务器。
- `surveying-ai-teacher-v21.5.zip.sha256`：网站包校验文件，一起上传。
- `LiteAvatar-OneClick-21.5.zip`：放到运行数字人的Windows电脑，解压后使用。
- 本操作文档：按顺序执行。

## 3. 在Workbench升级网站

### 第1步：确认版本

在阿里云Workbench终端运行：

```bash
sudo docker exec geoai_demo_legacy-app-1 node -p 'require("./package.json").version'
df -h /opt
```

版本应为21.4.0（21.2.0/21.3.0也支持）。构建镜像和数据库、上传文件备份需要额外空间，脚本不会自动清理数据卷。保留旧目录、备份和原数字人网关。

### 第2步：建立上传目录

```bash
sudo mkdir -p /home/admin/surveying-releases/v21.5
sudo chown admin:admin /home/admin/surveying-releases/v21.5
```

在Workbench左侧真正进入 `/home/admin/surveying-releases/v21.5`，上传网站ZIP和SHA256文件。不要仅创建目录后就继续；文件必须确实位于该目录。

### 第3步：校验

```bash
cd /home/admin/surveying-releases/v21.5
ls -lh surveying-ai-teacher-v21.5.zip surveying-ai-teacher-v21.5.zip.sha256
sha256sum -c surveying-ai-teacher-v21.5.zip.sha256
```

必须显示 `surveying-ai-teacher-v21.5.zip: OK`。找不到文件先核对上传位置；校验不通过则重新下载上传。

### 第4步：解压到新目录

整段执行：

```bash
sudo python3 - <<'PY'
from pathlib import Path
import zipfile
archive=Path('/home/admin/surveying-releases/v21.5/surveying-ai-teacher-v21.5.zip')
target=Path('/opt/surveying-ai-teacher-step21.5')
assert not target.exists(), '21.5目录已经存在。请检查上次结果，不要直接覆盖。'
with zipfile.ZipFile(archive) as z:
    for name in z.namelist():
        p=Path(name)
        assert p.parts and p.parts[0]=='surveying-ai-teacher-step21.5' and '..' not in p.parts and not p.is_absolute(), '压缩包路径异常'
    z.extractall('/opt')
print('解压完成：',target)
PY
```

### 第5步：后台升级

```bash
actual_old_dir="$(sudo docker inspect geoai_demo_legacy-app-1 --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}')"
printf '实际旧目录：%s\n' "$actual_old_dir"
sudo systemd-run --unit=surveying-upgrade-v215 --description='Surveying upgrade to 21.5' /bin/bash /opt/surveying-ai-teacher-step21.5/scripts/v21-5-upgrade.sh "$actual_old_dir"
```

查看进度：

```bash
sudo journalctl -u surveying-upgrade-v215 -f --no-pager
```

这里按Ctrl+C仅退出日志查看，后台升级仍继续。不要按Ctrl+Z暂停升级，也不要重复执行升级命令。

脚本会先核对现有版本、配置及实际数据卷，再构建镜像并运行临时数据库检查。旧网站在构建期间继续工作，切换前短暂停止以备份数据库和上传文件。切换检查失败会尝试恢复旧应用。现有独立LiteAvatar网关、SSH账号、隧道和TURN不会由本脚本重建。

“Started”只代表后台任务启动，不代表升级成功。若显示“已有升级正在进行”或同名单元已存在，先检查：

```bash
sudo systemctl show surveying-upgrade-v215 -p ActiveState -p SubState -p Result -p ExecMainStatus
sudo journalctl -u surveying-upgrade-v215 -n 100 --no-pager
```

不要删除锁文件或在仍有升级运行时另开一个任务。

### 第6步：确认完成

日志出现“升级完成”后：

```bash
sudo cat /opt/surveying-ai-teacher-step21.5/V215_UPGRADE_SUCCESS
sudo docker exec geoai_demo_legacy-app-1 node -p 'require("./package.json").version'
sudo bash /opt/surveying-ai-teacher-step21.5/scripts/v21-5-verify.sh https://localhost
```

预期显示21.5.0并通过检查。保存成功标记中的备份路径。刷新教师网页，必要时按Ctrl+F5。

若只完成构建，没有成功标记，不要认定升级完成。保留最后报错，再定位问题。

### 必要时回退

只有确认升级任务已结束、决定回到旧网站时执行：

```bash
backup_dir="$(sudo cat /opt/surveying-ai-teacher-step21.5/LAST_BACKUP)"
sudo bash /opt/surveying-ai-teacher-step21.5/scripts/v21-5-rollback.sh "$backup_dir"
```

回退恢复原应用镜像与相关配置，不自动倒退数据库，不丢弃升级后的新增记录。不要删除数据库卷。若数据库本身损坏，需要另行核对备份再恢复，不能盲目覆盖。

## 4. 在Windows安装一键启动器：只做一次

### 第7步：固定保存位置

在运行数字人的那台Windows电脑上解压 `LiteAvatar-OneClick-21.5.zip`。建议把其中的 `liteavatar215` 文件夹放到固定位置，例如：

```text
C:\LiteAvatar215\liteavatar215\
```

其中应有 `Setup.cmd`、`Start-Classroom.cmd`、`Start-Public.cmd`、`Stop.cmd`、`Logs.cmd`、`Launcher.ps1`、`manager.py` 等。不要在压缩包预览窗口里直接运行，也不要上传到阿里云代替本机安装。

它复用原有 `~/OpenAvatarChat/.venv`、模型及 `~/OpenAvatarChat/start_teacher_tunnel.sh`。不会重新下载几GB模型。必须是此前运行成功的WSL Ubuntu环境。

### 第8步：首次设置

双击 `Setup.cmd`，按提示输入：

| 英文提示 | 你的操作 |
|---|---|
| WSL distribution name | 输入列表中安装OpenAvatarChat的发行版名称。如确实是Ubuntu，直接回车；若是Ubuntu-24.04，输入完整名称。 |
| Ubuntu user | 通常输入gordon，默认直接回车。不选root。 |
| Paste Bailian API Key (hidden) | 粘贴有权限且余额正常的百炼API Key，输入隐藏。不要填网站的OAC_BRIDGE_KEY。 |
| Register website launch button? | 输入Y或直接回车，注册网页启动链接。 |
| Start classroom service on Windows login? | 希望登录Windows后自动运行就输入Y；只想需要时一键启动就输入N或回车。 |

密钥通过Windows当前用户的DPAPI加密保存在 `%LOCALAPPDATA%\SurveyingLiteAvatar215\key.dpapi`，不写进网站源码、网页链接或命令行参数。换Windows用户或换电脑后请重新Setup。

注册后不要移动这个文件夹。如移动，重新运行新位置的Setup.cmd更新关联。

如果原先两个Ubuntu窗口仍在运行，首次切换前分别在数字人服务和旧SSH隧道窗口按Ctrl+C停止它们。启动器不会强杀旧窗口里的其他进程。

### 第9步：启动课堂数字人

双击 `Start-Classroom.cmd`。

启动器会自动：调用所选WSL和gordon用户 → 读取课堂配置 → 启动LiteAvatar → 运行原SSH隧道 → 等待本机服务响应 → 打开教师网页。

不需要再手动运行source、python或ssh。首次载入模型需要等待。启动窗口可以最小化，请保持运行。

如果课堂配置尚未生成，且原公网配置 `config/local_liteavatar_public.yaml` 存在，启动器会创建课堂扩展。已经存在的 `config/local_liteavatar_classroom213.yaml` 会保留，不自动覆盖。

进入教师网页后仍需正常登录，在数字教师界面选择LiteAvatar并点击连接/开始；涉及麦克风时允许浏览器权限。公网数字人网关若提示已有的独立用户名/密码，按原方式登录。启动器不取消网站或网关认证。

“本机网页服务已响应，隧道进程运行中”不是整个WebRTC音视频链路验收完成；首次应实际让数字人说一句话，确认声音和嘴型。

### 第10步：以后每次使用

**不启用Windows登录自启时：**

1. 开机联网。
2. 双击Start-Classroom.cmd；或进入教师PPT页面点击“一键启动本机LiteAvatar”，在浏览器提示中确认打开。
3. 等人物服务就绪，选择LiteAvatar、连接并授课。
4. 下课结束网页会话后双击Stop.cmd，停止本启动器管理的数字人和隧道。

**启用Windows登录自启时：**

登录Windows后启动器自动在后台启动并显示最小化窗口。等加载完成即可到教师网页连接。无需再开Ubuntu窗口。若登录时网络尚未就绪且重试后失败，联网后双击Start-Classroom.cmd即可。

同一时间仅启动一个模式。启动器运行时再次点击不会另起第二套服务；需要切换模式先Stop.cmd，再启动。停止不是卸载，不删除模型或课件。

**独立语音问答：** 双击Start-Public.cmd，使用原 `local_liteavatar_public.yaml`，打开 `https://localhost:8443/`。课堂模式则使用网站的课程问答/讲解业务。两种模式不能同时占用8282端口。

## 5. PPT全屏、翻译和朗读怎么用

1. 登录 [教师页面](https://localhost/teacher)，进入“课堂交互PPT”。
2. 从已有课件库选中PPT并点击“在讲授台展示”。上传和课件库仍沿用21.4。
3. 等页面载入后点击“全屏”。现在只有幻灯片舞台进入真正全屏，右侧翻译面板和网站导航隐藏。
4. 用←/→或PageUp/PageDown翻页。鼠标移到屏幕底部可显示控制栏，点击上一页/下一页也可以。Esc退出。
5. 点击PPT文字、拖选短语或双击句子后，翻译显示在幻灯片上方的底部字幕框；“字幕开/关”控制显示。字幕覆盖幻灯片，不挤压幻灯片尺寸。
6. 点“朗读译文”读当前翻译；打开“自动朗读”后，下次翻译完成会自动读。点“停止朗读”立即停止。
7. 字幕和朗读可以单独开关：只看字幕、只听朗读或两者同时使用。
8. 全屏底部点“AI讲解本页”时会先退出PPT浏览器全屏，再打开原数字教师界面，防止数字教师窗口被全屏层挡住。

浏览器朗读与LiteAvatar嘴型朗读是两条不同输出：翻译朗读使用系统/浏览器声音；数字人讲解继续使用原LiteAvatar/CosyVoice。系统未安装可用中文声音、浏览器阻止自动播音时，点击“朗读译文”重试，并检查Windows中文语音与音量。没有中文声音时字幕仍可用。不要同时开启两种朗读导致声音重叠。

复杂动画、嵌入媒体、特殊字体仍受网页PPT渲染器支持范围限制；本次解决完整页面显示和全屏，不宣称与PowerPoint所有动画完全一致。

## 6. 故障定位

| 现象 | 先检查 |
|---|---|
| 网页按钮没有启动 | 在运行数字人的Windows电脑上安装并运行Setup.cmd注册；其他电脑/手机不能靠这个链接启动你的主机。也可直接双击Start-Classroom.cmd。 |
| 提示WSL发行版不存在 | 重新Setup，输入列表里的准确发行版名称。 |
| 找不到虚拟环境或隧道脚本 | 确认选了原来gordon用户和安装OpenAvatarChat的那套Ubuntu。不要创建新的空环境代替它。 |
| 提示8282已有服务 | 原服务仍在运行。先关闭原数字人服务；不要盲目重复启动或删除配置。 |
| 隧道连续失败 | 检查联网、原SSH私钥/known_hosts和旧隧道是否还占用云端18282。启动器保持StrictHostKeyChecking原设置，不关闭主机身份校验。 |
| 502 Bad Gateway | 确认启动器未关闭、电脑未休眠、隧道未失败；双击Logs.cmd检查日志。云端网关本身也可能需要进一步排查。 |
| 页面有声音但没人物/嘴型 | 检查数字人页面会话、TURN/WebRTC和LiteAvatar日志，不能只根据本机HTTP状态判断。 |
| 数字人无声，apiKey required或Arrearage | Setup重新填有效百炼Key；在百炼核对权限与余额。浏览器翻译朗读正常不能证明CosyVoice账户正常。 |
| 想取消Windows登录自启 | 再运行Setup.cmd，最后一项选N。网页启动关联继续保留。 |
| 不同文件名的本机配置 | 本版按你此前用过的两个配置名连接；不要随意把不相关配置改名覆盖，请提供去掉密钥后的文件名与报错再调整。 |

双击Logs.cmd可看本机最近日志。日志只做常见密钥脱敏；分享前仍检查是否含课程内容或个人信息。不要发送完整API密钥、.env、私钥、portal-login.txt。
