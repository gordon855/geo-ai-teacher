## Reproduce in a NEW isolated demo

Do not seed an instance with user courseware: this changes the current PPT and
writes fictional records. The script requires an explicit flag, a generated demo
project name and loopback origin. Keep .audit/integration-state.json for verify.

```powershell
# Only if the fresh checkout has no .env:
npm run demo:setup
docker compose config --quiet
docker compose up --build --wait --wait-timeout 300
node --env-file=.env scripts/demo-http-smoke.mjs
$env:GEOAI_INTEGRATION_TEST='1'
node --env-file=.env scripts/demo-integration.mjs seed
docker compose stop
docker compose up --wait --wait-timeout 180
node --env-file=.env scripts/demo-integration.mjs verify
```

For this already tested instance, use verify, not seed. After first password
changes, initial .env login passwords are intentionally obsolete. Set process
CLASSROOM_ADMIN_PASSWORD and DEMO_STUDENT_1_PASSWORD to the changed values before
verify; DEMO_STUDENT_PASSWORD remains the unchanged second student's password.
Never commit credentials or shared logs.

Local evidence: .audit/docker-*-20261027.log, .audit/integration-*-results.json,
and ignored browser artifacts. For this local acceptance only, generated changed
teacher/student-1 credentials are in .audit/browser-credentials.env. It is private
and excluded from release.

## Boundaries and current state

Provider translation, GPU/LiteAvatar inference, RTC/TURN, microphone, ASR/TTS,
external map stability, remote TLS/proxy and production-scale migration remain
unverified. Existing production data was not imported or touched. No Windows
system setting changed. Docker's binary and credential helper were made visible
using process-only PATH; a new terminal may inherit the installer's PATH.

Both services are left running at http://localhost:3000.
Use `docker compose stop` to pause and `docker compose up --wait` to resume with
the same .env and volumes. Do not use volume removal commands.
