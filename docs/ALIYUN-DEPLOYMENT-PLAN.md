# 阿里云或其他服务器部署/升级说明（人工执行计划）

本轮未登录或修改任何云服务器。根 Compose 已通过本机独立部署测试；这不证明
既有阿里云实例可直接原位升级。历史升级脚本保留但入口禁用，不要绕过保护运行。

建议先在用户自己批准的独立测试环境中验收，不复用现有学校数据库、OSS、数据卷
或正式域名。本项目不会自动购买资源或更改安全组。

1. 明确目标实例、目录、Compose 项目名、容量和维护窗口；确认源码/教材/模型授权。
2. 对现有应用先做数据库、上传文件、私有配置和可回退镜像备份，并在隔离实例
   测试恢复。禁止把真实备份放入公开仓库。
3. 在新目录放置审阅后的候选源码，生成新 .env 和新项目名，使用根 Compose
   启动新库；按 Docker 验收报告检查登录、课件、成绩、权限和重启持久化。
4. 远程访问需自备 HTTPS 反向代理，设置实际 CLASSROOM_PUBLIC_ORIGIN、
   ROOT_DOMAIN/WWW_DOMAIN 和隐私联系方式。应用保持回环端口，数据库不开放公网。
   若代理也运行在容器中，须按其网络拓扑单独配置并验收，不照搬宿主回环地址。
5. 若要迁移真实教学数据，先在受控环境核对源版本、表结构和逐项迁移差异，
   制定文件与数据库一致性方案并获得操作授权。演示 seed 不能替代生产迁移。
6. 人工试用并确认回退路径后再批准域名/流量切换。若失败，切回旧实例；
   不把新版数据库直接交给旧代码，除非已测试兼容性。
7. API Key/模型/数字人网关只在运行时配置，分别核对许可与现场设备能力。

本说明不是已完成的阿里云升级记录，也未授权任何生产操作。
